            Every API call in the flow (`Register`, `Users`, `Exchange/corridors`, `Exchange/affiliateRates`, `Providers`, `Lookups/types`, `Exchange/rates`, `InitiateHostedTransaction`, `CompleteHostedPayment`) is logged below:

            Streamlined Olowo × MITO Integration Flow

            1. Step 1 — Unified User/Sender Registration (`/register` & `/login`): User registration happens at the beginning in one single form collecting all personal, account, and residential address fields, and immediately submits to POST /api/olowo/auth/register & POST /api/v1/mito/Users to obtain the MITO userId. No separate KYC page is shown.
            2. Step 2 — Get Corridors & Show Rates (`/remittances/create`): Calls GET /api/v1/mito/Exchange/corridors & GET /api/v1/mito/Exchange/affiliateRates?userId=<userId> using the dynamic userId from Step 1 (never hardcoded) to display live corridors and commercial exchange rates.
            3. Step 3 — Select Bank (`GET /api/v1/mito/Providers`): Based on the selected receive country/currency and collection mode (BANKACCOUNT or MOBILEMONEY), fetches providers via GET /api/v1/mito/Providers so the user selects the destination bank/provider right on the Rate screen.
            4. Step 4 — Lock Rate & Submit Transaction (`POST /Exchange/rates` → `POST /Transactions/InitiateHostedTransaction`): Locks the exchange rate with the selected providerId (starting the side expiry countdown timer) and submits the transaction to MITO.
            5. Step 5 — MITO Hosted Page Continues Flow (`requiredAction`): MITO returns a hosted page in response that continues the flow for creating/selecting the beneficiary, any required info if needed, and completing payment, then redirects to /remittances/callback.
